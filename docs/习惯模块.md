# 习惯模块复刻需求与任务清单

目标页面：`https://dida365.com/webapp/#q/all/habit`

## 1. 复刻依据

### REA 运行时观察

- 页面路由：`#q/all/habit`，习惯详情为 `#q/all/habit/<habitId>`。
- 主界面：顶部周条、习惯列表 / 卡片、右侧详情面板。
- 习惯行：图标、名称、总打卡天数、当前连续天数、最近 7 天打卡圈。
- 添加 / 编辑习惯字段：图标、名称、频率、目标、开始日期、坚持天数、所属分组、提醒、自动弹出打卡日志。
- 频率：按天（选择星期）、按周（每周 N 天）、按时间间隔（每 N 天）。
- 目标：当天完成打卡、当天完成一定量。
- 详情：月打卡、总打卡、月完成率、当前连续、月完成量、总完成量、月历热力、每日完成量、月度打卡日志。
- 详情菜单：编辑、开始专注、打卡样式（对勾 / 习惯图标）、归档、删除。
- 全局菜单：设置（今天/最近 7 天显示、按完成状态分类显示）、导出。

### REA 静态 / 网络证据

REA 对下载的 JS 树执行了 `analyze_javascript_application`，并保留了 Evidence。大体量 `web.ap` 在分析时触发 worker 堆限制，因此同时使用了运行时网络观测与静态字符串检索补足。

观察到的数据接口：

```text
GET  /api/v2/habits
GET  /api/v2/habitSections
POST /api/v2/habits/batch
POST /api/v2/habitSections/batch
POST /api/v2/habitCheckins/query
POST /api/v2/habitCheckins/batch
POST /api/v2/getHabitRecords
GET  /api/v2/user/preferences/habit?platform=web
PUT  /api/v2/user/preferences/habit?platform=web
GET  /api/v2/data/export/habits
```

习惯核心字段：`name`、`iconRes`/图标、`color`、`sectionId`、`sortOrder`、`status`、`goal`、`step`、`unit`、`repeatRule`/频率、`reminders`、`recordEnable`、`startDate`/`targetStartDate`、`targetDays`、`exDates`、`style`。

打卡字段：`habitId`、`checkinStamp`（YYYYMMDD）、`checkinTime`、`value`、`goal`、`status`（0 未标记、1 未完成、2 完成）。

日志字段：`habitId`、`stamp`、`content`、`emoji`。

## 3. 当前实现说明

本轮已经提供可用的 P0 闭环：

- 数据存储在本项目 SQLite，不写入 CalDAV `VTODO`。
- 打卡按日期唯一，`value >= goal` 视为完成。
- 连续天数与月完成率由后端按频率和打卡记录实时计算。
- 习惯列表、详情、周条、月历、图表和日志都使用真实 API 数据。
- 未实现的 P1/P2 项继续保留在上面的清单中。

### 本地 API

```text

POST   /api/admin/habits
PATCH  /api/admin/habits/{id}
DELETE /api/admin/habits/{id}
POST   /api/admin/habits/{id}/checkin
GET    /api/admin/habits/{id}/detail?month=YYYY-MM
POST   /api/admin/habits/{id}/records
PATCH  /api/admin/habits/{id}/records/{recordId}
DELETE /api/admin/habits/{id}/records/{recordId}
GET    /api/admin/habit-preferences
PATCH  /api/admin/habit-preferences
GET    /api/admin/habit-sections
POST   /api/admin/habit-sections
PATCH  /api/admin/habit-sections/{id}

```

## 4. 尚未对齐的行为

- Dida 使用 RRULE 表达频率；当前使用等价的本项目 JSON 配置。
- Dida 的 `currentStreak`、`maxStreak`、月完成率在按周/间隔模式下有更细的周期规则，当前使用近似算法。
- Dida 的“打卡样式”与“开始专注”尚未接入当前前端。
- Dida 的今天/最近 7 天、日历联动和提醒投递尚未接入。
- Dida 的导出为服务端文件流；当前导出 CSV，字段仍可继续对齐。
