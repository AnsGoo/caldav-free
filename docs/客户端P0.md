## 3. 本地库

> **P0 实际实现说明**：构建时 pub.dev 不可达（本机代理节点故障），无法拉取
> drift / build_runner，因此 P0 使用 `LocalStore` 接口背后的**原子 JSON 文件**
> 实现（临时文件 + rename、单写队列、损坏文件自动备份）。下面的 SQL 是 P1
> 迁移到 drift/SQLite 时的目标 schema，字段与同步协议一一对应。
> 迁移只替换 `lib/data/db/`，同步引擎与 UI 不需要改。

P0 只建同步需要的表：

```sql
task (
  id TEXT PRIMARY KEY, list_id TEXT NOT NULL, parent_id TEXT,
  section_id TEXT, title TEXT NOT NULL, notes TEXT NOT NULL DEFAULT '',
  kind TEXT NOT NULL DEFAULT 'TASK', priority INTEGER NOT NULL DEFAULT 0,
  start_at INTEGER, due_at INTEGER, all_day INTEGER NOT NULL DEFAULT 0,
  recurrence TEXT NOT NULL DEFAULT '', reminders TEXT NOT NULL DEFAULT '[]',
  tags TEXT NOT NULL DEFAULT '[]', checklist TEXT NOT NULL DEFAULT '[]',
  assignee TEXT NOT NULL DEFAULT '', completed_at INTEGER,
  pinned_at INTEGER, sort_order INTEGER NOT NULL DEFAULT 0,
  deleted INTEGER NOT NULL DEFAULT 0, deleted_at INTEGER,
  etag TEXT NOT NULL DEFAULT '', version INTEGER NOT NULL DEFAULT 0,
  dirty INTEGER NOT NULL DEFAULT 0, updated_at INTEGER NOT NULL
);

task_list (
  id TEXT PRIMARY KEY, folder_id TEXT, name TEXT NOT NULL,
  color TEXT NOT NULL DEFAULT '', kind TEXT NOT NULL DEFAULT 'TASK',
  sort_order INTEGER NOT NULL DEFAULT 0, pinned INTEGER NOT NULL DEFAULT 0,
  is_inbox INTEGER NOT NULL DEFAULT 0, etag TEXT NOT NULL DEFAULT '',
  version INTEGER NOT NULL DEFAULT 0, dirty INTEGER NOT NULL DEFAULT 0,
  updated_at INTEGER NOT NULL
);

sync_state (scope TEXT PRIMARY KEY, cursor TEXT NOT NULL, synced_at INTEGER NOT NULL);
outbox (
  op_id TEXT PRIMARY KEY, entity TEXT NOT NULL, entity_id TEXT NOT NULL,
  action TEXT NOT NULL, base_etag TEXT, patch TEXT NOT NULL,
  attempts INTEGER NOT NULL DEFAULT 0, next_try_at INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL
);
sync_conflict (
  entity TEXT, entity_id TEXT, local_patch TEXT, remote TEXT, created_at INTEGER,
  PRIMARY KEY(entity, entity_id)
);
```

写路径：UI → 本地事务（写业务表 + outbox + dirty=1）→ 触发同步。UI 永不直接调用远端。

## 4. 同步状态机

```text
idle → pulling → merging → pushing → settling → idle
          │          │          │
          └─ network ─┴─ conflict ┴→ backoff / conflict
```

- 单飞：同一时刻只跑一个 `sync()`。
- 每页 pull 在一个事务内落库并推进游标。
- 合并使用 outbox patch 的字段集合判断「本地脏字段」；脏字段本地赢，其余取远端。
- 完成态：`completed_at` 取较早的非空值。
- 删除：远端 `deleted=true` 或 tombstone 一律覆盖本地。
- push 结果：
  - `ok`：覆盖 etag/version，删 outbox。
  - `conflict`：用返回快照与本地 patch 合并，更新 etag，重试。
  - `gone`：物理删除本地行，删 outbox。
  - `error`：指数退避，超过 8 次标记失败并在诊断页展示。
- 触发：冷启动、下拉刷新、本地写、每 15 秒前台轮询、网络恢复（P1）。

## 5. 登录与校验

1. 输入服务器地址、用户名、密码。
2. 调用 `GET /api/sync/pull?since=0&limit=1`（Basic Auth）：401/403 提示凭据错误，200 认为可用。
3. 成功后把服务器地址、用户名、密码和设备 ID 写入应用私有目录的
   `credentials.json`。P0 没有 `flutter_secure_storage`（同样受依赖环境限制），
   这是**明文文件**；Android 上仅本应用可读，P1 必须迁移到 Keystore/Keychain。
4. 首次登录执行 `fullSync`（cursor=0），之后按游标增量。
5. 退出登录：清空任务、游标、outbox、冲突和凭据（保留设备 ID）。

## 7. 与总体方案的偏差

| 项 | 方案 | P0 实现 | 原因 |
| --- | --- | --- | --- |
| 本地库 | drift + SQLite | 原子 JSON 文件（`LocalStore`） | 构建环境无法访问 pub.dev，拉不到 drift/build_runner；接口已隔离，P1 替换实现 |
| 代码生成 | freezed + json_serializable | 手写不可变模型 + 手写 JSON | 减少 P0 构建链复杂度 |
| 状态管理 | Riverpod | `provider` + `ChangeNotifier` | 缓存里只有 provider；P1 可平移到 Riverpod |
| 推送提示 | SSE | 15 秒轮询 + 本地写防抖 | P0 先保证正确性；SSE 在 P1 接入 |
| 分段包 | `packages/core` / `packages/data` | 单包内 `lib/core` / `lib/data` | 单端开发期减少工具链成本；P6 前再拆 |
| 安全存储 | Keychain / Keystore | 应用私有目录 JSON（明文） | 依赖不可达；P1 安全加固第一项 |
| 路由 | go_router | `home` 按会话切换 | P0 只有登录/任务/诊断三页 |
