# 鸿蒙应用签名

本项目当前的签名状态：`ohos/build-profile.json5` 里 `signingConfigs: []`，即**完全未签名**。
模拟器能装是因为它放宽了校验；真机必须签名才能安装，代理提醒（定时提醒）也必须有带权益的签名包才生效。

## 一、先分清三种包

| 包类型 | 怎么来 | 能装哪 | 带代理提醒权益 |
|---|---|---|---|
| unsigned | `hvigorw assembleHap` 直接产物 | 仅模拟器 | ❌ |
| 自动签名 debug | DevEco 勾「Automatically generate signature」 | 已注册 UDID 的真机 / 模拟器 | ❌（自动签名不带管控能力） |
| 手动签名 + 带权益 Profile | 本机 keystore + AGC 证书 + AGC Profile | 任意（Profile 里列的设备/或发布） | ✅ |

结论：**只想在真机上跑起来 → 走路线 A；想让 60 秒定时提醒真正由系统弹 → 必须走路线 B。**

## 二、路线 A：DevEco 自动签名（约 1 分钟）

1. DevEco Studio 打开 `mobile/ohos`（注意不是 `mobile` 根目录）
2. 右上角 **File → Project Structure → Project → Signing Configs**
3. 勾选 **Automatically generate signature**
4. 点 **Sign In** 登录华为开发者账号（需已实名）
5. 等待自动生成，点 **OK**
6. 此时 `build-profile.json5` 的 `signingConfigs` 会自动被填入 4 个字段，证书落在 `~/.ohos/config/`

自动签名会把 `signingConfig` 与 product 绑定，之后 `./mobile/scripts/build-ohos.sh --fast` 产出的就是已签名包（`entry-default-signed.hap`），不用再跑 `sign-ohos.sh`。

## 三、路线 B：手动签名（AGC 全流程）

### 第 1 步：本机密钥 + CSR —— 已完成 ✅

已生成（`mobile/ohos/signature/`，已在 `.gitignore` 中排除）：

```
caldav-free.p12     密钥库，别名 caldav-free-key
caldav-free.csr     证书请求文件，待上传 AGC
```

- 密钥算法：ECC NIST-P-256
- 密钥库口令 / 密钥口令：写在 `mobile/ohos/signature/.pwd`（整个目录已 gitignore），`sign-ohos.sh` 自动读取；也可用 `CALDAV_KEY_PWD` / `CALDAV_STORE_PWD` 环境变量覆盖
- Subject：`C=CN, O=CaldavFree, OU=Mobile, CN=CaldavFree Debug`

重新生成（如需换算法或口令）：

```bash
JB=/Applications/DevEco-Studio.app/Contents/jbr/Contents/Home/bin/java
TOOL=/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/toolchains/lib/hap-sign-tool.jar
cd mobile/ohos/signature
$JB -jar $TOOL generate-keypair -keyAlias caldav-free-key -keyPwd '你的口令' \
  -keyAlg ECC -keySize NIST-P-256 -keystoreFile "$PWD/caldav-free.p12" -keystorePwd '你的口令'
$JB -jar $TOOL generate-csr -keyAlias caldav-free-key -keyPwd '你的口令' \
  -subject "C=CN,O=YourOrg,OU=Mobile,CN=YourApp" -signAlg SHA256withECDSA \
  -keystoreFile "$PWD/caldav-free.p12" -keystorePwd '你的口令' -outFile "$PWD/caldav-free.csr"
```

### 第 2 步：AGC 建应用 + 申请证书

进入 [AppGallery Connect](https://developer.huawei.com/consumer/cn/service/josp/agc/index.html)：

1. **我的项目 → 添加项目 → 添加应用**
   - 包名必须**一字不差**：`com.caldavfree.caldav_free`
   - 设备类型勾「手机」
2. **证书、APP ID 和 Profile → 证书 → 新增证书**
   - 名称：`caldav-free-debug`
   - 类型：**调试证书**（真机自测选这个；要上架才用发布证书）
   - 上传 `mobile/ohos/signature/caldav-free.csr`
   - 下载 `.cer`，放到 `mobile/ohos/signature/caldav-free-debug.cer`

### 第 3 步：注册调试设备（仅调试证书需要）

```bash
HDC=/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/toolchains/hdc
$HDC list targets                     # 确认设备在线
$HDC shell bm get -u                  # 真机取 UDID
```

AGC → **设备管理 → 添加设备**，把 UDID 填进去（每台要装的设备都要注册，模拟器一般不需要）。

### 第 4 步：申请代理提醒开放能力（1700002 的真正解药）

这是四环链，缺任何一环都是同一个 `1700002`：

1. **申请权益**：AGC → 我的项目 → **项目设置 → 开放能力管理 → 代理提醒 → 申请**
2. **批复后勾开关**：同一页面勾选「代理提醒」并点右上角**保存**（很多人卡在这一步）
3. **重新生成 Profile**：只有新 Profile 才带 `app-services-capabilities` / `restricted-permissions` 字段
4. **用新 Profile 重新签包**：旧 Profile 签出来的包等于没权益

#### 别申请「优先通知」

AGC 开放能力列表里有一堆相近的名字，只有「代理提醒」是 1700002 的解药：

| 能力 | 管什么 | 本项目 |
|---|---|---|
| **代理提醒** | 进程被杀后仍能到点弹提醒，权限 `ohos.permission.PUBLISH_AGENT_REMINDER` | ✅ 要申请这个 |
| 优先通知 | 通知在通知栏里优先显示（排序靠前），不负责定时 | ❌ 只对商务类、社交通讯类开放，且要求应用内有「重要联系人 / @我 / 加急消息」功能，要交对应功能截图。日历应用必然被拒 |
| Calendar Kit | 把事件写进系统日历，由日历提醒 | 备选（见下） |
| Push Kit | 服务端推送到设备 | 需要自建服务端，不合本项目的本地提醒定位 |

#### 申请材料怎么填（本项目可直接照抄）

**先确认「应用分类」不是空的** —— 这是最常见的被拒原因。进
AGC → **APP → 应用上架 → 应用信息**，把分类填好并保存，再截图。审核既看应用分类
（须在工具/商务/效率/生活服务/旅游/医疗/运动健康/教育/金融理财/游戏之内），
也看提醒场景，**两张截图要一起提交**：应用分类截图 + 功能场景截图。

| 字段 | 填什么 |
|---|---|
| 应用介绍 | CalDAV 日历客户端，用户同步自有日历账户，为日程设置到点提醒 |
| 使用场景 | 用户在日程里设定提醒时间；应用退到后台或被系统回收、设备锁屏时，仍需按设定时间弹出提醒 |
| 申请用途 | 日程提醒、时间提醒、到期提醒（属官方开放清单里的「生活类提醒」） |
| 通知标题 | 日程提醒 |
| 通知文本 | `{日程标题} 即将开始` |
| 通知频率 | 由用户逐条设置，单条日程一次 |
| 承诺 | 仅用于用户自行创建的日程提醒，不做营销推送，不超出申请场景使用 |

两个细节会直接影响审核：

- **文案要与代码一致。** 上表填的标题/文本，必须和 `NotifyBridge.ets` 里真实下发的字符串对得上，
  审核方会核对。
- **截图要能看见提醒本身。** 若设置页的提醒项还没做完，可以临时打开构建一个 debug 包截一张，
  截完再改回去。

审核约 8 个工作日。被拒时可以补材料重提，也可以发邮件到 `hwpush@huawei.com`，
主题写 `[Request for the Agent-Powered Reminder Permission]`，正文附包名、场景、
文案、频率，10 个工作日内回复。

#### 走不通时的备选：Calendar Kit

官方在管控说明里给出的替代方案就是把日程写进系统日历，由日历负责提醒。对 CalDAV 客户端
来说这条路其实更自然（本来就在同步日历事件），但它同样要单独申请 Calendar Kit 的权益，
不是免申请的旁路。

### 第 5 步：创建 Profile

AGC → **证书、APP ID 和 Profile → Profile → 添加**

- 名称：`caldav-free-debug-profile`
- 类型：**调试**
- 选择应用：`com.caldavfree.caldav_free`
- 选择证书：第 2 步生成的证书
- 勾选设备：第 3 步注册的设备
- 受限权限：确认 `ohos.permission.PUBLISH_AGENT_REMINDER` 已列出（未开通能力这里看不到）
- 下载 `.p7b` → 放到 `mobile/ohos/signature/caldav-free-debug.p7b`

### 第 6 步：签 + 装

```bash
./mobile/scripts/sign-ohos.sh --check     # 检查素材是否齐
./mobile/scripts/sign-ohos.sh --install   # 签名并安装启动
```

脚本做的事：找 `entry-default-unsigned.hap` → `hap-sign-tool sign-app -mode localSign` → 输出 `entry-default-signed.hap` → `verify-app` 校验 → `hdc install -r` + `aa start`。

底层命令（脚本失败时手动排查用）：

```bash
$JB -jar $TOOL sign-app \
  -mode localSign -keyAlias caldav-free-key -keyPwd '口令' \
  -appCertFile caldav-free-debug.cer -profileFile caldav-free-debug.p7b -profileSigned 1 \
  -inFile entry-default-unsigned.hap -signAlg SHA256withECDSA \
  -keystoreFile caldav-free.p12 -keystorePwd '口令' \
  -outFile entry-default-signed.hap -compatibleVersion 26 -signCode 1
```

## 四、让 hvigor 直接出签名包（可选）

如果不想每次手动跑脚本，把素材路径写进 `ohos/build-profile.json5`：

```json5
"signingConfigs": [
  {
    "name": "default",
    "type": "HarmonyOS",
    "material": {
      "certpath": "./signature/caldav-free-debug.cer",
      "storePassword": "把 signature/.pwd 的内容填这里，明文",
      "keyAlias": "caldav-free-key",
      "keyPassword": "同上",
      "profile": "./signature/caldav-free-debug.p7b",
      "signAlg": "SHA256withECDSA",
      "storeFile": "./signature/caldav-free.p12"
    }
  }
]
```

> 注意：`certpath` / `profile` 是相对 `ohos/build-profile.json5` 的路径；`type` 必须写 `HarmonyOS`（不是 `OpenHarmony`，否则真机拒绝安装）。
> 写错任一路径会让 hvigor 直接报「签名配置校验失败」，比手签更容易踩坑，所以本项目默认不写死，交给 `sign-ohos.sh`。

配好之后：

```bash
./mobile/scripts/build-ohos.sh --fast    # 产物自动是 signed
```

## 五、报错对照表

| 现象 | 原因 |
|---|---|
| `9568289 / install failed due to grant request permissions failed` | Profile 里没列该受限权限，或用了旧 Profile |
| `1700002` | 四环链断：没申请 / 没勾开关 / Profile 没重新生成 / 包没用新 Profile 重签 |
| `error: failed to install bundle. code:9568322` | 证书与 Profile 不匹配（证书换过但 Profile 没重新生成） |
| `The bundleName in profile is not match` | AGC 应用包名与 `AppScope/app.json5` 不一致 |
| `verify-app` 失败但能装 | debug 证书链校验宽松，属正常 |
| `Cannot find the profile file` | `-profileFile` 路径写错，或 `.p7b` 其实是网页下载的 html |

## 六、安全

- `mobile/ohos/signature/` 含私钥，**已加入 `.gitignore`**，不要提交、不要外传
- 口令明文只出现在本地脚本默认值里，正式发布前改成环境变量注入
- 换机器时迁移 `.p12` + `.cer` + `.p7b` 三件套即可，Profile 换设备要重新生成
