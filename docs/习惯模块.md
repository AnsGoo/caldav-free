# 习惯模块复刻需求与任务清单

目标页面：`https://dida365.com/webapp/#q/all/habit`

## 1. 复刻依据

### REA 运行时观察

- 页面路由：`#q/all/habit`，习惯详情为 `#q/all/habit/<habitId>`。
- 主界面：顶部周条、习惯列表 / 卡片、右侧详情面板。
- 习惯行：图标、名称、总打卡天数、当前连续天数、最近 7 天打卡圈。
- 添加 / 编辑习惯字段：图标、名称、频率、目标、开始日期、坚持天数、所属分组、提醒、自动弹出打卡日志。
- 频率：按天（选择星期）、按周（每周 N 天）、按时间间隔（每 N 天）。
- 目标：当天完成打卡、当天完成一定量。
- 详情：月打卡、总打卡、月完成率、当前连续、月完成量、总完成量、月历热力、每日完成量、月度打卡日志。
- 详情菜单：编辑、开始专注、打卡样式（对勾 / 习惯图标）、归档、删除。
- 全局菜单：设置（今天/最近 7 天显示、按完成状态分类显示）、导出。

### REA 静态 / 网络证据

REA 对下载的 JS 树执行了 `analyze_javascript_application`，并保留了 Evidence。大体量 `web.ap` 在分析时触发 worker 堆限制，因此同时使用了运行时网络观测与静态字符串检索补足。

习惯核心字段：`name`、`iconRes`/图标、`color`、`sectionId`、`sortOrder`、`status`、`goal`、`step`、`unit`、`repeatRule`/频率、`reminders`、`recordEnable`、`startDate`/`targetStartDate`、`targetDays`、`exDates`、`style`。

打卡字段：`habitId`、`checkinStamp`（YYYYMMDD）、`checkinTime`、`value`、`goal`、`status`（0 未标记、1 未完成、2 完成）。

日志字段：`habitId`、`stamp`、`content`、`emoji`。

## 3. ### 提醒投递

习惯提醒复用现有提醒基础设施：

- 调度器每 30 秒检查一次
- 只处理启用、今日到期且今日未完成的习惯
- 每个 HH:mm 提醒独立去重
- 站内通知类型为 `habit`
- Web Push 复用 `NotifyUser`
- 邮件复用 SMTP 配置
- 内部使用负数 `task_id` 复用 `reminder_deliveries` / `reminder_attempts`，避免与任务 ID 冲突
- 失败使用现有指数退避重试

当前实现说明

P0 闭环与以下 P1 已完成：打卡样式切换、分组管理、习惯拖拽排序、日志编辑。

- 数据存储在本项目 SQLite，不写入 CalDAV `VTODO`。
- 打卡按日期唯一，`value >= goal` 视为完成。
- 连续天数与月完成率由后端按频率和打卡记录实时计算；按周目标按与月份重叠的自然周累计，单周完成量按目标封顶。
- 间隔打卡使用 UTC 日期差，避免夏令时 23/25 小时导致漏算。
- JSON 备份导入支持 `append`（新增副本）、`skip`（跳过同名）、`overwrite`（覆盖同名）三种模式；分组按名称复用。
- 单习惯导出保留该习惯、所属分组、打卡、日志和专注历史；CSV 仅导出打卡明细。
- Dida XLSX 导入读取每个工作表首个单元格的基本信息（名称、状态、目标、分组、提醒、频率），再读取“日期/时间/完成情况/完成量/心情/日志”表格；`其他` 分组映射为未分组。
- 公开分享使用随机 token，只读展示名称、图标、统计和最近 30 天打卡，不展示日志、备注、邮箱或账号信息；可撤销并立即失效。
- 公开分享 API 按客户端 IP 限流（60 次/分钟），超限返回 `429` 和 `Retry-After`。
- 并发打卡由进程内互斥锁串行化读改写，并用唯一索引冲突 upsert 兜底；同一习惯同一天不会产生重复行。
- 习惯列表、详情、周条、月历、图表和日志都使用真实 API 数据。
- 未实现的 P1/P2 项继续保留在上面的清单中。
