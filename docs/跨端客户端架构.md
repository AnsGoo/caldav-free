# 跨端客户端架构方案（Flutter × 5 平台）

> 目标：Android / iOS / macOS / Windows / HarmonyOS Next 五端，一套代码
> 后端：本仓库 `caldav-free`（Go + SQLite + CalDAV）
> 前置事实：见 `docs/滴答清单Android逆向.md`
> 本文只定方案，不含业务实现

---

## 1. 结论与关键决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 跨端框架 | **Flutter** | 首端四平台成熟，HarmonyOS 有官方 SIG 分支；自绘 UI 最适合还原滴答的列表/看板/时间线 |
| 本地库 | **drift（SQLite）+ 手写同步内核** | 关系模型复杂、需要事务与增量查询；不引入第三方同步 SaaS |
| 状态管理 | **Riverpod** | 编译期安全、易测试、适合「本地库为唯一真相」的响应式流 |
| 同步模型 | **cursor 增量拉取 + outbox 批量推送 + ETag** | 直接对齐滴答的 `checkPoint / SYNC_STATUS / id2etag` |
| 后端改造 | 新增 pull / push 两个 API（已实现） | 现有 REST 是「页面驱动」，不适合离线客户端 |
| HarmonyOS | 主方案 Flutter OHOS，**ArkWeb 壳为兜底** | OHOS 分支版本滞后、插件生态不全，必须先做 1 周 spike |
| 代码组织 | 单 App + 内部分层包 | 避免 monorepo 工具链成本；用 `melos` 只做脚本编排 |

**一句话**：客户端把「服务端当远程数据库」，本地库是唯一真相，UI 只读本地库；网络层只负责增量同步。

### 2.1 HarmonyOS 的现实约束（必须先验证）

- 社区方案基于 Flutter 3.7.12 / 3.22 的 **OHOS 分支**（`openharmony-sig/flutter_flutter`），不是 upstream 主线。
- 常用插件（path_provider、shared_preferences、sqlite3、flutter_local_notifications）需要 `_ohos` 版本或自写 channel。
- `drift` 依赖 `sqlite3` FFI：需要在 OHOS 上编译/内置 `libsqlite3.so`，或改用 OHOS 原生 RDB 的适配层。
- 结论：**先做 spike**（1 周）验证「SQLite + 通知 + 文件」三件事；不通过就切 ArkWeb 壳（Web 端复用现有 Vue 工作台，能力降级但可交付）。

## 3. 总体架构

```text
┌──────────────────────────────────────────────────────────────┐
│ app/  Flutter 单应用                                          │
│  ├─ features/   任务 清单 看板 时间线 日历 矩阵 习惯 专注 …    │
│  ├─ design/     主题 token、组件库、图标、动效                 │
│  └─ platform/   通知/小组件/托盘/快捷键/分享/生物识别           │
├──────────────────────────────────────────────────────────────┤
│ packages/core/            领域模型 + 规则（纯 Dart，无 IO）     │
│  ├─ entity/      Task Project Column Tag Filter Habit …        │
│  ├─ rule/        RRULE 展开、过滤器 DSL、排序、自然语言解析      │
│  └─ sync/        合并策略、变更集、冲突判定（纯函数）           │
├──────────────────────────────────────────────────────────────┤
│ packages/data/           本地库 + 远端 + 同步引擎               │
│  ├─ db/         drift schema、DAO、迁移                        │
│  ├─ remote/     HTTP 客户端、DTO、鉴权、重试                    │
│  └─ engine/     SyncEngine（pull / merge / push / settle）      │
└──────────────────────────────────────────────────────────────┘
        │                                   │
        ▼                                   ▼
   SQLite（唯一真相）                  caldav-free /api/admin/sync/*
```

**依赖方向**：`features → core`、`features → data`、`data → core`；`core` 不依赖 Flutter，可在纯 Dart 测试里跑完整同步逻辑。

**为什么不把服务端 JSON 直接当模型**：滴答的线上模型有 60+ 字段且历史包袱重；领域模型应按「界面需要什么」收敛，DTO 只在 `data/remote` 出现。

## 5. 本地库设计（drift）

### 5.1 表

```sql
-- 业务镜像（服务端数据的本地副本）
CREATE TABLE task (
  id           TEXT PRIMARY KEY,
  list_id      TEXT NOT NULL,
  parent_id    TEXT,
  section_id   TEXT,
  title        TEXT NOT NULL,
  notes        TEXT NOT NULL DEFAULT '',
  kind         INTEGER NOT NULL DEFAULT 0,
  priority     INTEGER NOT NULL DEFAULT 0,
  start_at     INTEGER, due_at INTEGER,
  all_day      INTEGER NOT NULL DEFAULT 0,
  time_zone    TEXT NOT NULL DEFAULT 'Asia/Shanghai',
  rrule        TEXT,
  ex_dates     TEXT,                     -- JSON 数组
  reminders    TEXT,                     -- JSON
  tags         TEXT,                     -- JSON
  progress     INTEGER NOT NULL DEFAULT 0,
  pinned_at    INTEGER,
  completed_at INTEGER,
  assignee     TEXT,
  sort_order   INTEGER NOT NULL DEFAULT 0,
  deleted      INTEGER NOT NULL DEFAULT 0,
  version      INTEGER NOT NULL DEFAULT 0,
  etag         TEXT,
  dirty        INTEGER NOT NULL DEFAULT 0,   -- outbox 冗余位，便于查询
  updated_at   INTEGER NOT NULL
);
CREATE INDEX idx_task_list ON task(list_id, deleted, completed_at);
CREATE INDEX idx_task_due  ON task(due_at) WHERE deleted=0;

-- 清单 / 分组 / 列 / 标签 / 过滤器
CREATE TABLE task_list   (id TEXT PRIMARY KEY, name TEXT, color TEXT, kind INTEGER,
                          view_mode TEXT, sort_order INTEGER, group_id TEXT,
                          sort_option TEXT, deleted INTEGER, version INTEGER,
                          etag TEXT, dirty INTEGER, updated_at INTEGER);
CREATE TABLE task_group  (...);
CREATE TABLE section     (id TEXT PRIMARY KEY, list_id TEXT, name TEXT,
                          sort_order INTEGER, deleted INTEGER, version INTEGER,
                          etag TEXT, dirty INTEGER, updated_at INTEGER);
CREATE TABLE tag         (id TEXT PRIMARY KEY, name TEXT, color TEXT, parent TEXT,
                          sort_order INTEGER, deleted INTEGER, version INTEGER,
                          etag TEXT, dirty INTEGER, updated_at INTEGER);
CREATE TABLE filter      (id TEXT PRIMARY KEY, name TEXT, rule TEXT, sort_order INTEGER,
                          deleted INTEGER, version INTEGER, etag TEXT,
                          dirty INTEGER, updated_at INTEGER);

-- 习惯 / 专注 / 倒数日（二期）
CREATE TABLE habit (...);
CREATE TABLE habit_checkin (habit_id TEXT, day TEXT, value INTEGER, PRIMARY KEY(habit_id, day));
CREATE TABLE focus_session (...);
CREATE TABLE countdown (...);

-- 同步内核
CREATE TABLE sync_state (
  scope       TEXT PRIMARY KEY,   -- 'tasks' | 'columns' | 'settings'
  cursor      TEXT NOT NULL,      -- 服务端游标（opaque）
  synced_at   INTEGER NOT NULL,
  full_sync_at INTEGER
);

CREATE TABLE outbox (
  op_id       TEXT PRIMARY KEY,   -- 客户端 ULID，服务端幂等键
  entity      TEXT NOT NULL,      -- task | list | section | tag | filter
  entity_id   TEXT NOT NULL,
  action      TEXT NOT NULL,      -- create | update | delete | move | reorder
  base_etag   TEXT,               -- 冲突检测
  patch       TEXT NOT NULL,      -- 只存改动字段
  attempts    INTEGER NOT NULL DEFAULT 0,
  next_try_at INTEGER NOT NULL DEFAULT 0,
  created_at  INTEGER NOT NULL
);
CREATE UNIQUE INDEX idx_outbox_entity ON outbox(entity, entity_id, action);

CREATE TABLE tombstone (          -- 本地已删、待服务端确认
  entity TEXT, entity_id TEXT, deleted_at INTEGER,
  PRIMARY KEY(entity, entity_id)
);

CREATE TABLE sync_conflict (      -- 冲突待用户处理
  entity TEXT, entity_id TEXT, local TEXT, remote TEXT, created_at INTEGER,
  PRIMARY KEY(entity, entity_id)
);

-- 搜索
CREATE VIRTUAL TABLE task_fts USING fts5(title, notes, tags, content=task, content_rowid=rowid);
```

### 5.2 关键约束

1. **UI 不直接调远端**：任何写操作先写本地 + 写 outbox，再触发同步。
2. **outbox 幂等**：`op_id` 由客户端生成，服务端按 `(user, op_id)` 去重，重试不会重复建任务。
3. **删除分两级**：`deleted=1`（回收站）与物理删除；`tombstone` 只用于跨设备传播。
4. **排序用稀疏整数**：新插入取相邻两项中点（`(a+b)/2`），间隔耗尽时把该清单重排并整体推送一次（对齐滴答的 `syncOrderBean`）。
5. **多账号**：所有表加 `account_id` 或按账号分库文件（推荐分文件，注销即删）。
6. **加密**：用 SQLCipher（`sqlcipher_flutter_libs`）可选开启；密钥放 Keychain/Keystore/Credential Manager。

## 6. 同步引擎

### 6.1 状态机

```text
idle ──(本地写/定时/SSE/手动)──► pulling ──► merging ──► pushing ──► settling ──► idle
                                   │            │           │
                                   └── 网络失败 ─┴─ 冲突 ────┴─► backoff / conflict
```

- 单飞（single-flight）：同一时刻只允许一个同步任务。
- 拉取与推送可并行，但**合并必须在同一事务**里完成。
- SSE/WebSocket 只作为「该同步了」的提示，不承载数据。

### 6.2 拉取

```dart
Future<void> pull() async {
  var state = await db.syncState('tasks');
  var cursor = state.cursor;
  while (true) {
    final page = await api.pull(since: cursor, limit: 500);
    await db.transaction(() async {
      for (final dto in page.tasks) { await mergeTask(dto); }
      for (final dto in page.lists) { await mergeList(dto); }
      for (final t in page.tombstones) { await applyTombstone(t); }
      await db.setCursor('tasks', page.cursor);
    });
    if (!page.hasMore) break;
    cursor = page.cursor;
  }
}
```

要点：
- 游标是**不透明字符串**（服务端可以是 `seq`），客户端不解析。
- 每页在一个事务里落库，保证「游标推进」和「数据写入」原子。
- 首次登录或服务端版本升级时做一次 `fullSync`（不带游标，服务端分批下发）。

### 6.3 合并（核心）

```dart
Future<void> mergeTask(TaskDTO remote) async {
  final local = await db.taskById(remote.id);
  if (local == null) { await db.insertTask(remote.toEntity()); return; }

  final hasPending = await db.hasOutbox('task', remote.id);

  if (!hasPending) {                       // 本地干净：直接覆盖
    await db.upsertTask(remote.toEntity());
    return;
  }

  if (local.etag == remote.etag) return;   // 同一版本，无需处理

  // 本地有未推送修改：三方合并（base = 上次同步快照）
  final base = await db.syncedSnapshot('task', remote.id);
  final merged = fieldMerge(base: base, local: local, remote: remote);

  if (merged.conflicts.isNotEmpty) {
    await db.saveConflict(remote.id, local, remote);
  }
  await db.upsertTask(merged.entity..dirty = true);
}
```

`fieldMerge` 的规则（纯函数，可单测）：

| 字段类别 | 规则 |
| --- | --- |
| 标量（标题、备注、优先级、日期、进度） | 本地脏字段赢；未脏字段取远端 |
| 集合（标签、提醒、子任务） | 并集 + 删除墓碑；同 id 以本地为准 |
| 结构（清单归属、父任务、看板列） | 以最后修改时间为准；相同时间远端优先 |
| 排序 | 服务端顺序优先，本地仅在「本设备刚拖拽」时保留 |
| 完成态 | 谁先完成谁赢（`completed_at` 取较早非空值） |
| 删除 | 删除赢（服务端墓碑优先） |

> 这套规则与滴答的 `TASK_SYNCED_JSON` + `skipETagCheck` 思路一致：**没有 base 快照就无法做字段级合并**，所以快照表必须有。

### 6.4 推送

```dart
Future<void> push() async {
  final ops = await db.takeOutbox(limit: 100);
  if (ops.isEmpty) return;

  final res = await api.push(deviceId: deviceId, ops: ops);

  await db.transaction(() async {
    for (final r in res.results) {
      switch (r.status) {
        case 'ok':
          await db.applyEtag(r.entity, r.entityId, r.etag, r.version);
          await db.removeOutbox(r.opId);           // 用服务端回的 etag 覆盖本地
          break;
        case 'conflict':
          await db.saveConflict(r.entityId, local: r.local, remote: r.entity);
          await db.removeOutbox(r.opId);           // 交给合并流程
          break;
        case 'gone':
          await db.hardDelete(r.entityId);
          await db.removeOutbox(r.opId);
          break;
        default:
          await db.backoff(r.opId);                // 指数退避，最多 N 次
      }
    }
  });
}
```

- 批量上限 100 条 / 请求；超过则分片。
- 失败指数退避：1s → 2s → 4s → … 上限 5 min；`attempts > 8` 标记为「同步异常」并在设置页展示。
- 网络恢复、App 前台、SSE 事件、手动下拉都触发 `sync()`。

### 6.5 服务端协议（已实现，2026-10-25）

详细字段、状态码与示例见 [`docs/同步协议.md`](同步协议.md)。摘要：

```http
GET /api/sync/pull?since=<cursor>&limit=500&refresh=0
Authorization: Basic ...
→ 200 {
    "cursor": "128",
    "hasMore": false,
    "serverTime": "2026-10-25T08:00:00Z",
    "tasks": [ { "id": "...", "etag": "v127", "version": 127, "deleted": false, ... } ],
    "lists": [...], "sections": [...], "folders": [...], "filters": [...],
    "tombstones": [ { "entity": "list", "id": "...", "deletedAt": "..." } ]
  }

POST /api/sync/push
Authorization: Basic ...
{ "deviceId": "...",
  "ops": [ { "opId": "01J...", "entity": "task", "entityId": "01J...",
             "action": "update", "baseEtag": "v127", "patch": { "title": "x" } } ] }
→ 200 { "cursor": "130",
        "results": [ { "opId": "...", "status": "ok|conflict|gone|error",
                       "etag": "v129", "version": 129, "entity": {...},
                       "error": {"code": "etag_mismatch", "message": "..."} } ] }
```

实现要点：

1. **认证**：HTTP Basic（复用 CalDAV 凭据缓存）；不接收会话 Cookie，因此没有 CSRF 流程。
2. **游标**：用户级 `sync_logs.id`，由 SQLite 触发器在所有写路径（工作台 REST、AI、CalDAV 对账）上自动写入；客户端不解析。
3. **实体 ID**：`sync_id` 是客户端可生成的 ULID；历史数据回填为数字字符串。引用字段（`listId/parentId/sectionId/folderId`）全部使用同步 ID。
4. **ETag/version**：实体最后一次日志序号，格式 `v<seq>`；push 带 `baseEtag` 时不一致返回 409 语义的 `conflict` 结果和最新快照。
5. **幂等**：`sync_ops` 按 `(user, opId)` 去重 7 天；重试返回首次结果。日志保留 90 天。
6. **CalDAV 一致性**：pull/push 前最多每 10 秒执行一次 VTODO 对账；`refresh=1` 可强制对账。CalDAV 侧写入通过同一份日志进入增量流。
7. **SSE**：仍复用 `/api/admin/tasks/stream` 作为「该 pull 了」的提示，不承载数据。
8. **当前范围**：`task/list/section/folder/filter`。习惯、专注、倒数日、评论/附件尚未纳入。

**后端已交付**：`internal/store/sync.go`（日志、触发器、回填）、`internal/syncapi`（pull/push、DTO、冲突与幂等）、`internal/web/sync.go`（Basic Auth 路由）、`scripts/sync-curl-demo.sh`（两端并发修改演示）。

## 8. 设计系统

- **Token 三层**：`primitives`（色阶/字号/间距）→ `semantic`（surface/text/accent/danger）→ `component`（行高、卡片圆角）。
- 主题：先做逆向里确认的 12 套纯色（默认、晴蓝、松石、秘青、蒹葭、杏黄、桃夭、暮山紫、沉香、藏蓝、灰色、暗夜）+ 跟随系统；城市/季节/摄影主题作为资源包后置。
- 密度：桌面端 `compact`（行高 36）、移动端 `comfortable`（行高 52），同一套组件按 `MediaQuery` + 断点切换。
- 键盘：桌面端实现滴答的快捷键表（`N` 新建、`Tab+M` 完成、`Tab+P` 置顶、`V L/K/T` 切视图、`G` 序列导航、`⌘K` 命令面板）。用 `Shortcuts/Actions` + 可配置映射表，冲突检测在前。
- 无障碍：所有列表项提供 `Semantics`，支持动态字号；拖拽提供「移动到…」菜单作为替代路径。
- 动效：勾选使用 Lottie（可直接复用 APK 里的 `assets/animation_checkbox_click.json` 这类资源做视觉参考，不复用文件本身）。

## 9. 工程与质量

| 项 | 方案 |
| --- | --- |
| 代码生成 | `freezed` + `json_serializable` + `drift_dev` + `riverpod_generator` |
| 网络 | `dio` + 拦截器（鉴权、重试、日志脱敏） |
| 路由 | `go_router`（支持桌面深链、移动端返回栈） |
| 时间 | `timezone` + `rrule`（RRULE 展开在 `core` 内做，避免平台差异） |
| 通知 | `flutter_local_notifications`（四端）+ OHOS 自写 channel |
| 安全存储 | `flutter_secure_storage`（Keychain / Keystore / Credential Manager） |
| 崩溃 | `sentry_flutter`（自托管可选） |
| 测试 | 纯 Dart 单测（同步/合并/规则）+ `drift` 内存库集成测试 + `integration_test` 冒烟 |
| 黄金测试 | `alchemist` 或 `golden_toolkit`，覆盖列表/看板/详情三态（浅色/深色/紧凑） |
| CI | GitHub Actions：`analyze` → `test` → 四端构建 → 产物上传；OHOS 单独 job |
| 发布 | Android AAB（Play/国内渠道）、iOS TestFlight、macOS notarize、Windows MSIX、OHOS HAP |

**同步内核的测试策略**（最关键）：

1. 纯函数测 `fieldMerge` 的全部字段组合。
2. 用内存 SQLite 跑「两端并发修改 → 收敛」的属性测试（property-based）。
3. 注入网络故障（丢包、超时、409、500）验证 outbox 幂等与退避。
4. 时钟偏移/时区切换/夏令时用例。

## 12. 附：与现有 Web 前端的关系

`web/` 的 Vue 工作台继续作为「管理后台 / 大屏 / 分享页」存在，不替代原生客户端。

- 共享：设计 token（CSS 变量 ↔ Dart token 用同一份 JSON 生成）、API 契约、主题清单。
- 不共享：交互层。移动端的滑动手势、桌面端的快捷键与多窗口，Web 端无法等价实现。
- 过渡：HarmonyOS 若走 ArkWeb 兜底，直接复用 `web/` 构建产物，仅补登录态与通知桥。
