# 跨境部署与回源方案

> 记录 `https://caldav-free.example.com` 客户端无法登录的根因分析，以及两条可落地的恢复路线。
>
> 状态：**根因已确认（境内 ICP 备案拦截）**，方案待选型执行。
>
> 文中域名、IP 已替换为占位符（`example.com` / `<ECS_IP>`），按实际环境替换即可。

---

## 一、结论速览

| 项目 | 结论 |
|---|---|
| 根因 | 域名 `example.com` 未完成 ICP 备案，服务部署在阿里云**北京** ECS |
| 与 macOS 日志的关系 | **无关**。`TSM` / `IMK` 是输入法子系统噪音 |
| 服务端状态 | **正常**。nginx、证书、Go 应用、SQLite 均无问题 |
| 普通 Cloudflare 代理（橙云回源） | **无效**，回源仍带未备案域名 `Host`/`SNI`，照样被拦 |
| Cloudflare Tunnel | **有效**，出站反向隧道，公网无入站流量到 ECS |
| 迁往香港 / 海外 ECS | **有效**，境外服务器无需 ICP 备案 |
| 改端口 | **无效**，拦截按 SNI 匹配，与端口无关 |

## 二、问题诊断

### 2.1 排除的误报

启动时终端打印的两行日志：

```
TSM AdjustCapsLockLEDForKeyTransitionHandling - _ISSetPhysicalKeyboardCapsLockLED Inhibit
error messaging the mach port for IMKCFRunLoopWakeUpReliable
```

- `TSM`（Text Services Manager）、`IMK`（Input Method Kit）属于 **macOS 输入法与键盘子系统**。
- 由 Terminal / iTerm / 输入法框架触发，`caldav-free` 只是恰好在这个进程里往 stderr 打印日志。
- 本项目是纯 Go HTTP 服务，`cmd/caldav-free/main.go` 中没有任何 GUI 或输入法代码。
- **结论：完全无害，可忽略。**

### 2.2 实测证据

所有测试在 2026-11-01 执行。

| # | 测试 | 结果 | 判定 |
|---|---|---|---|
| 1 | `dig @1.1.1.1 caldav-free.example.com` | `<ECS_IP>` | 直指阿里云北京 ECS，未经任何 CDN |
| 2 | `curl -D- http://域名/` | `403`，`Server: Beaver`，标题 `Non-compliance ICP Filing`，跳转 `aliyun.com/beian/beian-block` | **阿里云备案拦截页** |
| 3 | `openssl s_client -connect IP:443 -servername 域名` | `SSL_ERROR_SYSCALL` / `read 0 bytes` | 443 同样被拦 |
| 4 | `openssl s_client -connect IP:443 -servername example.com` | 握手成功，证书 `CN=caldav-free.example.com` | **nginx 与证书完全正常** |
| 5 | `openssl s_client -connect IP:8443 -servername example.com` | 握手成功，证书 `CN=music-free-serve` | 同机其他站点在运行 |
| 6 | `openssl s_client -connect IP:8443 -servername 域名` | 握手失败 | 拦截与端口无关，只看 SNI |
| 7 | 境外网络 `GET http://域名/` | `403` | 拦截在**源站侧**，与请求来源 IP 无关 |
| 8 | `nc -vz IP 5232` | Empty reply | 安全组未放行，应用未暴露公网 |
| 9 | `openssl ... -servername 域名.`（尾点）/ 大写 | 均失败 | 无大小写/尾点绕过 |

### 2.3 关键结论

```
                  ┌──────────────────────────────┐
客户端 ──TLS──▶   │ 阿里云北京 ECS 公网入口       │
  SNI=未备案域名  │ 按 Host/SNI 匹配 → 直接丢弃    │  ✗
                  └──────────────────────────────┘
```

拦截**打在服务器公网入口、按域名匹配**，所以：

- 换请求来源 IP（VPN / 代理 / 境外）→ 无效（证据 7）
- 换端口（8443）→ 无效（证据 6）
- 换 Cloudflare 橙云回源 → 无效（回源请求仍带该域名 Host/SNI）
- 换 NS / 换解析商 → **无效**，拦截依据不是解析

## 三、两条可行路线

### 路线 A：Cloudflare Tunnel（沿用现有北京机器）

**适用**：不想买新服务器，需要当天恢复。

**原理**：`cloudflared` 从服务器**主动出站**建立到 Cloudflare 的长连接，公网流量只到 Cloudflare 边缘，不进入 ECS 的 80/443，因此不触发备案拦截。

```
客户端 ──HTTPS──▶ Cloudflare 边缘 ──(反向隧道)──▶ cloudflared(北京) ──HTTP──▶ 127.0.0.1:5232
```

**耗时**：约 15 分钟（不含 DNS 生效等待）
**成本**：0
**代价**：Cloudflare 免费版在中国大陆的边缘调度不稳定，CalDAV 增量同步会时快时慢

---

### 路线 B：迁移到香港 / 海外 ECS

**适用**：追求长期稳定，可以多一台机器。

**原理**：境外服务器不受 ICP 备案管辖，域名 A 记录直接指向境外 IP 即可。

**耗时**：1–2 小时
**成本**：一台低配 ECS，约 ¥60–100/月
**代价**：需要迁移 + 重新签发证书

---

## 四、路线 A：Cloudflare Tunnel 完整步骤

### 4.0 前置检查

在北京机器上执行，确认现状：

```bash
systemctl status caldav-free --no-pager
systemctl status cloudflared-quick-tunnel --no-pager
sudo ss -lntp | grep -E ':(5232|5233|80|443)\b'
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5232/healthz
```

预期：`5232` 有 Go 应用监听，`/healthz` 返回 `200`。

### 4.1 导出全部 DNS 记录（重要）

⚠️ 把 `example.com` 的 NS 切到 Cloudflare 会**接管所有子域**，包括同机那个 `music-free-serve`（8443 端口）。切之前必须把阿里云云解析里的记录全部抄下来：

```bash
# 在能访问阿里云 API 的机器上，或直接在控制台截图
# 控制台：云解析 DNS → example.com → 解析设置 → 导出
```

至少核对这几类：`A`、`AAAA`、`CNAME`、`MX`、`TXT`（SPF / 域名验证）、`NS`（子域委派）。

### 4.2 在 Cloudflare 接管域名

1. Cloudflare Dashboard → **Add a site** → 输入 `example.com` → 选 **Free**
2. Cloudflare 自动扫描现有记录 → **逐条与 4.1 的导出结果核对**，缺失的手工补
3. 记录 Cloudflare 分配的两个 NS，例如 `xxx.ns.cloudflare.com` / `yyy.ns.cloudflare.com`
4. 阿里云 → 域名 → `example.com` → **DNS 修改** → 改为上述两个 NS
5. 等待生效（通常 10 分钟–2 小时）：

```bash
dig +short NS example.com @1.1.1.1
# 出现 *.ns.cloudflare.com 即生效
```

> 生效后阿里云云解析即失效，所有记录以 Cloudflare 为准。

### 4.3 安装 cloudflared

```bash
# Debian / Ubuntu
curl -fsSL https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb \
  -o /tmp/cloudflared.deb
sudo dpkg -i /tmp/cloudflared.deb
cloudflared --version

# CentOS / Alibaba Cloud Linux
# sudo rpm -ivh https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-x86_64.rpm
```

> 国内下载 GitHub Releases 可能很慢。可在本地下载后用 `scp` 传上去。

### 4.4 授权并创建命名隧道

```bash
cloudflared tunnel login
# 终端会打印一个 URL，复制到浏览器打开
# 必须选中 example.com 并授权
# 成功后会在 ~/.cloudflared/cert.pem 生成授权文件

cloudflared tunnel create caldav-free
# 输出示例：
#   Tunnel credentials written to /root/.cloudflared/6ff42ae2-765d-4adf-8112-31c55c1551ef.json
#   记下这个 UUID
```

### 4.5 写入隧道配置

```bash
sudo mkdir -p /etc/cloudflared
TUNNEL_ID="把上面的 UUID 填这里"

sudo tee /etc/cloudflared/config.yml >/dev/null <<EOF
tunnel: ${TUNNEL_ID}
credentials-file: /root/.cloudflared/${TUNNEL_ID}.json

ingress:
  # 仅暴露 CalDAV，管理后台保持私网
  - hostname: caldav-free.example.com
    service: http://127.0.0.1:5233
  - service: http_status:404

originRequest:
  connectTimeout: 30s
  noTLSVerify: false
  httpHostHeader: caldav-free.example.com
EOF
```

**两种暴露档位，按需选择：**

| 配置 | `service` | 效果 |
|---|---|---|
| 仅 CalDAV（推荐） | `http://127.0.0.1:5233` | 走 `scripts/cloudflared-caldav-proxy.py`，只放行 DAV 方法，挡掉 `/admin`、`/login` |
| 全站 | `http://127.0.0.1:5232` | 管理后台也可公网访问，需靠应用自身 session 登录保护 |

### 4.6 绑定域名

```bash
cloudflared tunnel route dns caldav-free caldav-free.example.com
```

这会在 Cloudflare 自动创建一条 `CNAME` 指向 `<TUNNEL_ID>.cfargotunnel.com`，**必须保持橙云（Proxy）开启**。

### 4.7 切换为常驻服务

```bash
# 停用旧的 quick tunnel
sudo systemctl disable --now cloudflared-quick-tunnel 2>/dev/null

# 前台试跑，确认能连通
sudo cloudflared tunnel --config /etc/cloudflared/config.yml run

# 确认无误后 Ctrl+C，安装为 systemd 服务
sudo cloudflared service install
sudo systemctl enable --now cloudflared
sudo systemctl status cloudflared --no-pager
```

### 4.8 修正应用单元里的临时地址

`deploy/caldav-free.service` 当前把 `-caldav-url` 指向了一个临时 trycloudflare 域名，切换后必须改掉，否则管理后台展示的 CalDAV 地址仍是旧的：

```bash
sudo sed -i 's#-caldav-url .*#-caldav-url https://caldav-free.example.com#' \
  /etc/systemd/system/caldav-free.service

sudo systemctl daemon-reload
sudo systemctl restart caldav-free
```

> 也可以直接复用仓库里的 `deploy/caldav-free.service`，它已经把 `-external-url` 写成正式域名。

### 4.9 验证

```bash
# 1) 隧道状态
cloudflared tunnel info caldav-free

# 2) 健康检查
curl -sS -o /dev/null -w '%{http_code}\n' https://caldav-free.example.com/healthz
# 期望 200

# 3) 证书
echo | openssl s_client -connect caldav-free.example.com:443 \
  -servername caldav-free.example.com 2>/dev/null | grep subject=

# 4) CalDAV 认证
curl -i -u 用户名:密码 https://caldav-free.example.com/principals/
# 期望 207 Multi-Status

# 5) 确认备案页已消失
curl -sS -D- http://caldav-free.example.com/ -o /dev/null | head -5
```

### 4.10 ⚠️ 已知坑：反向代理脚本的上游协议

`scripts/cloudflared-caldav-proxy.py` 第 54 行硬编码：

```python
UPSTREAM_TLS = True
```

而 `deploy/caldav-free.service` 启动应用时**没有**加 `-tls-cert`，5232 是明文 HTTP。这意味着代理会用 HTTPS 去连一个 HTTP 端口，结果 `502 upstream unavailable`。

**二选一修复：**

方案 1（改脚本，推荐）：

```bash
sudo sed -i 's/^UPSTREAM_TLS = True$/UPSTREAM_TLS = False/' \
  /opt/caldav-free/cloudflared-caldav-proxy.py
```

或启动时显式指定：

```bash
python3 scripts/cloudflared-caldav-proxy.py --listen 127.0.0.1:5233 --upstream 127.0.0.1:5232
```

方案 2（给应用加 TLS）：在 systemd 单元里补 `-tls-cert` / `-tls-key`，让 5232 走 HTTPS。

> 若把隧道直接指向 `5232`（4.5 的"全站"档位），则不受此问题影响。

## 五、路线 B：迁移到香港 / 海外 ECS

### 5.1 选型建议

| 项 | 建议 |
|---|---|
| 地域 | 阿里云香港 / 新加坡，或腾讯云香港；预算敏感可选 Vultr / DigitalOcean |
| 配置 | 2 vCPU / 2 GB / 40 GB SSD 足够（SQLite 单文件，内存占用很低） |
| 系统 | Ubuntu 22.04 / 24.04 LTS（`deploy/` 里的 systemd 单元直接可用） |
| 带宽 | **至少 3 Mbps**；CalDAV 流量小，但客户端首次全量同步会拉满带宽 |
| 安全组 | 放行 `22`、`80`、`443` |
| 备案 | 香港及境外**无需 ICP 备案** |

### 5.2 旧机器：停机打包

```bash
# 确认数据目录与完整性
sudo systemctl cat caldav-free | grep ExecStart
sudo du -sh /var/lib/caldav-free
sqlite3 /var/lib/caldav-free/caldav-free.db 'PRAGMA integrity_check;'
# 期望 ok

# 停机 → 打包 → 立刻启回（停机窗口通常 < 10 秒）
sudo systemctl stop caldav-free
sudo tar czf /tmp/caldav-migrate.tgz -C /var/lib caldav-free
sudo cp /opt/caldav-free/caldav-free /tmp/caldav-free-bin
sudo systemctl start caldav-free

ls -lh /tmp/caldav-migrate.tgz /tmp/caldav-free-bin
```

> 顺带备份一份 TLS 证书，避免重新签发：
> `sudo tar czf /tmp/caldav-tls.tgz -C /etc/caldav-free tls`

### 5.3 中转下载

跨境内网直传通常很慢，建议本地中转：

```bash
# 本地执行
scp root@<ECS_IP>:/tmp/caldav-migrate.tgz /tmp/
scp root@<ECS_IP>:/tmp/caldav-free-bin /tmp/

scp /tmp/caldav-migrate.tgz root@<香港IP>:/tmp/
scp /tmp/caldav-free-bin   root@<香港IP>:/tmp/
```

### 5.4 新机器：初始化

```bash
# 系统用户
sudo useradd --system --home /var/lib/caldav-free --shell /usr/sbin/nologin caldav
sudo mkdir -p /var/lib/caldav-free /opt/caldav-free /etc/caldav-free/tls

# 还原数据
sudo tar xzf /tmp/caldav-migrate.tgz -C /var/lib
sudo chown -R caldav:caldav /var/lib/caldav-free
sudo chmod 700 /var/lib/caldav-free

# 安装二进制
sudo install -m 0755 /tmp/caldav-free-bin /opt/caldav-free/caldav-free
/opt/caldav-free/caldav-free -version

# 依赖
sudo apt update
sudo apt install -y nginx certbot python3-certbot-nginx sqlite3
```

### 5.5 安装 systemd 单元

```bash
sudo tee /etc/systemd/system/caldav-free.service >/dev/null <<'EOF'
[Unit]
Description=caldav-free CalDAV server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=caldav
Group=caldav
ExecStart=/opt/caldav-free/caldav-free \
  -addr 127.0.0.1:5232 \
  -data /var/lib/caldav-free \
  -external-url https://caldav-free.example.com \
  -caldav-url https://caldav-free.example.com
NoNewPrivileges=true
PrivateTmp=true
ProtectHome=true
ProtectSystem=strict
ReadWritePaths=/var/lib/caldav-free
Restart=on-failure
RestartSec=3
UMask=0077
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now caldav-free
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5232/healthz
```

### 5.6 nginx（先 HTTP，等证书）

```bash
sudo tee /etc/nginx/conf.d/caldav-free.conf >/dev/null <<'EOF'
server {
    listen 80;
    server_name caldav-free.example.com;

    location = /healthz {
        add_header Content-Type text/plain;
        return 200 "ok\n";
    }

    # 供 certbot --webroot 使用
    location /.well-known/acme-challenge/ {
        root /var/www/html;
    }

    location / {
        proxy_pass http://127.0.0.1:5232;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
        proxy_request_buffering off;
    }
}
EOF

sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

### 5.7 切换 DNS

在阿里云云解析把 `caldav-free.example.com` 的 `A` 记录从 `<ECS_IP>` 改为香港 IP，TTL 建议先设 60 秒。

> 此时旧站点对客户端本来就不可用，**切换不产生额外停机**。

```bash
# 等待生效
watch -n 5 'dig +short caldav-free.example.com @223.5.5.5'
```

### 5.8 签发证书

DNS 生效后执行：

```bash
sudo certbot --nginx -d caldav-free.example.com --redirect --agree-tos -m 你的邮箱
sudo systemctl status certbot.timer --no-pager   # 确认自动续期已启用
```

或者复用旧机器的证书（如果还没过期）：

```bash
# 本地：从旧机器拿到 /etc/caldav-free/tls/{fullchain,key}.pem
scp root@<ECS_IP>:/etc/caldav-free/tls/*.pem ./
scp ./*.pem root@<香港IP>:/etc/caldav-free/tls/
sudo chown root:root /etc/caldav-free/tls/*.pem
sudo chmod 600 /etc/caldav-free/tls/key.pem
```

证书就位后，把 5.6 的 server 块替换为仓库里的 `deploy/nginx-caldav-free.conf`（含 443、HTTP/2、HSTS、`.well-known/caldav` 直通、`client_max_body_size 20m`）。

### 5.9 验证

```bash
curl -sS -o /dev/null -w 'healthz=%{http_code}\n' https://caldav-free.example.com/healthz
curl -i -u 用户名:密码 https://caldav-free.example.com/principals/
echo | openssl s_client -connect caldav-free.example.com:443 \
  -servername caldav-free.example.com 2>/dev/null \
  | openssl x509 -noout -subject -dates
```

### 5.10 收尾

1. 确认新机器工作正常后，旧北京 ECS 上的 `caldav-free` 与 nginx 可以停掉或降级为备份：
   ```bash
   sudo systemctl disable --now caldav-free
   ```
2. **千万不要**把 DNS 再指回北京 IP，否则立刻恢复拦截。
3. 旧机器保留一份数据快照，至少一周。

## 六、方案对比

| 维度 | 路线 A（Tunnel） | 路线 B（香港 ECS） |
|---|---|---|
| 成本 | 0 | ¥60–100 / 月 |
| 生效时间 | 15 分钟 | 1–2 小时 |
| 国内访问质量 | 一般，依赖 CF 边缘调度 | 好，直连 |
| CalDAV 同步稳定性 | 中（偶发超时重试） | 高 |
| 是否需改 NS | **是**（接管整个域名） | 否（只改一条 A 记录） |
| 对其他子域的影响 | 需整体迁移解析记录 | 无 |
| 依赖外部服务 | Cloudflare | 仅服务器 |
| 管理后台暴露面 | 可只放 CalDAV | 全站，靠应用自身鉴权 |
| 长期维护 | CF 政策变动风险 | 自主可控 |

**推荐组合：先用路线 A 当天恢复，同时开通路线 B，一周内切过去。** 两者不冲突，切完 B 之后 A 的隧道可以直接关掉。

## 七、客户端配置

恢复后，各客户端填入：

| 客户端 | 服务器地址 | 备注 |
|---|---|---|
| macOS 日历 | `https://caldav-free.example.com` | 系统设置 → 互联网账户 → CalDAV |
| iOS / iPadOS | `caldav-free.example.com` | 设置 → 日历 → 账户 → 添加账户 → 其他 → CalDAV |
| DAVx5 (Android) | `https://caldav-free.example.com/` | 需要 Basic Auth 用户名密码 |
| Thunderbird | `https://caldav-free.example.com/principals/<用户名>/` | 新建日历 → 网络上 |
| GNOME Evolution | `https://caldav-free.example.com/` | 自动发现 `.well-known/caldav` |

> iOS/macOS 内置日历对重定向很敏感，所以 `deploy/nginx-caldav-free.conf` 里对 `/.well-known/caldav` 做了**直接代理**而非 301，切勿改回重定向。

## 八、回滚

### 路线 A 回滚

```bash
sudo systemctl disable --now cloudflared
sudo systemctl enable --now cloudflared-quick-tunnel   # 恢复旧的 quick tunnel
```

DNS 如需还原，在 Cloudflare 里把 `caldav-free` 的 CNAME 删掉即可。

### 路线 B 回滚


## 九、排障清单

| 症状 | 可能原因 | 排查命令 |
|---|---|---|
| `403 Non-compliance ICP Filing` | 仍指向境内未备案 IP | `dig +short 域名`，看是否还是 `<ECS_IP>` |
| TLS `read 0 bytes` | 同上，SNI 被拦 | `openssl s_client -servername 域名 -connect IP:443` |
| 隧道 `502 upstream unavailable` | 上游协议/端口不对（见 4.10） | `curl -v http://127.0.0.1:5232/healthz` |
| 隧道连不上 | NS 未生效 / CNAME 没建 | `cloudflared tunnel info`、`dig CNAME` |
| `421 Misdirected Request` | `httpHostHeader` 不匹配 | 检查 `config.yml` 的 `originRequest` |
| 客户端一直提示密码错误 | 反向代理丢了 `Authorization` 头 | `curl -u 用户:密码` 直接验证 |
| 客户端登录后看不到日历 | `.well-known/caldav` 走了 301 | 检查 nginx 配置是否改成直通 |
| 上传附件 413 | `client_max_body_size` 太小 | nginx 调 `30m` |
| 同步很慢 / 频繁超时 | CF 边缘调度到远端节点 | 优先考虑迁香港 |
